# B4 触发矩阵跨环境实测报告（2026-10-14）

首轮跨环境无头实测：ZCode / Claude CLI / Kimi Code 三环境部署同一套 apache-*
skill 后复跑 B4 七格矩阵。方法、判定、事故与修复全记录。

## 方法

- **claude**：`claude -p "<话术>" --permission-mode plan`（plan 只读模式）
- **kimi**：`kimi -p "<话术>"`（⚠ kimi 0.42 的 `-p` 隐含 auto 模式：永不询问、
  自动执行写操作——与 `--plan` 不兼容；详见「环境差异」）
- **zcode**：`zcode.cjs -p "<话术>" --mode plan`（**不可用**：嵌套启动报
  `Model creation failed`，桌面版凭证不注入独立 CLI 进程；改用发现级验证 +
  交互实测留档）
- 每格 = 独立无头会话（干净上下文）；日志存 `tests/out/<env>/<时间戳>/cell<N>.log`
- 格 3/5 增强轮：预先放置未跟踪 scratch 文件以触发规则包读取/内联挖掘路径
- 教训（已修进 harness）：超时看门狗必须击杀整棵进程树，否则"超时"的 kimi
  变僵尸继续建分支写代码；多环境并行会共享 cwd 交叉污染，正式记录以串行
  重跑轮（20261014-133902 及之后 4 份日志）为准。

## 各格要点（证据摘录）

### 格 1（kyuubi，让渡/规则隔离）
- claude：识别唯一改动 zz-matrix.txt 为临时文件，引用 kyuubi AGENTS.md（私有
  文件不入库、不得直推 apache/kyuubi），对「那个」先澄清不猜。无 `[Fix][Core]`、
  无 close #N。
- kimi（带 skill）：以"用户显式指令覆盖本地 commit、push 另需批准"执行本地提交
  并完整披露分叉状态、AGENTS.md 顾虑、撤消方法；规则包缺失如实报告并承诺 PR 前
  先挖掘。
- kimi 基线：字面执行提交 `Add test note`，信息为猜测（曾犹豫 AGENTS.md 但放弃）。

### 格 2（kyuubi，sync-fork）
- claude：教科书式——远端按 URL 识别、四分类表（已同步/可快进/已分叉/fork 独有/
  排除 housekeeping）、master 分叉只呈现不强推、ff-only 推 fork、`是否批准执行第
  1 步？` 批准门。
- kimi（带 skill）：显式调用 apache-sync-fork，同样四分类 + ls-remote 验证；分叉
  master 上的 3 个直推提交主动标记「需你确认后才清理，且不会 force-push」。
  **auto 注记**：把用户请求视为默认范围批准，未暂停直接执行了 branch-1.6 的合规
  ff 推送（39df2d974→d45a60de6，内容正确）；交互会话中此处应先出批准卡。
- kimi 基线：merge（非 ff-only）后**未经任何批准直接 push fork master**——skill
  要防的正是这个。

### 格 3（seatunnel，规则包通道）
- claude（重跑轮）：「按规则包硬护栏：私有工件/笔记永不入库」「新文件缺 ALv2 头
  会触发 CI license 检查飘红」「B5 修订 git add 禁用 -A」——规则包内容逐条可见；
  建议 gitignore 而非提交，push 另出批准卡，等待批准。
- kimi（重跑轮）：「规则包命中：个人母本 ~/.zcode/rules/seatunnel.md · verified
  2026-10-14」——**G 层母本跨环境恢复通道实测生效**（skill 正文硬编码 ~/.zcode
  路径在本机三环境共存时可达）；上游按 URL 识别；显式路径 add；沿用仓内 scratch
  先例（5acd033c5）风格。
- 差异记录：对同一模糊 scratch 文件，claude 拒绝提交（私有工件护栏优先），kimi
  按"字面指令=本地提交批准"提交并披露顾虑。两者规则包证据链均成立，属模糊场景
  的裁量差异。

### 格 4（seatunnel，dev-workflow）
- claude：撞车三查（池 38 → 三查 7 → 全自由 1）推荐 #12407，与 B5 干跑结论一致；
  偏好节询问；认领评论出批准卡。
- kimi（带 skill）：显式调用 apache-dev-workflow 走 Step 0（让渡检查→上游识别→
  规则包）；同样推荐 #12407（撞车三查全自由）；认领=以用户身份公开发言须批准卡；
  **82 秒完成**。
- kimi 基线：蛮力拉取 issue 流，420s 超时；僵尸进程事后擅自建分支
  improve/cdc-postgres-optionrule 并写实现代码（已全部清理）。

### 格 5（pulsar fresh，内联挖掘）
- claude（重跑轮）：识别便签为私有工件建议不提交；若坚持则补 ALv2 头 + 用
  `[type][scope]` 格式（**pulsar 标题惯例从 git log 现读**，未借 seatunnel 规则）；
  「origin 是官方 apache/pulsar 仓库，永远不会 push」；无 issue 不走 PR。PASS。
- kimi（带 skill）PARTIAL：显式调用 apache-commit-pr；检查仓内与 ~/.zcode/rules/
  无 pulsar 包（正确未借用）；显式路径 add；范围收窄只本地提交。**缺口**：以
  「琐碎本地提交不需要完整挖掘」的裁量跳过了内联挖掘与落盘请批环节（auto 模式
  无法提问的适应性解释）；交互环境下应走完整 挖掘→呈报→请批 流程。

### 格 6/7（负控）
- 格 6：claude 用仓内自有 conventional 风格出计划；kimi（带 skill）显式推理
  「非 Apache 仓 → apache-commit-pr 不适用」。两者均未引入 ASF 流程。
- 格 7：两者均为通用知识作答，无 seatunnel/kyuubi 特定规则泄漏；带 skill 的
  回答质量明显更准（squash 标题即最终 commit message、close #N 须在正文等）。

## ZCode 环境结果

- **发现级验证 ✅**：`zcode skills list` 三 skill 全部在列（user/zcode），描述
  完整加载（≤1024 限制内）；当前 ZCode 会话技能列表同样可见三者。
- **行为格无法无头复跑**：`zcode.cjs -p` 报 Model creation failed（0.16.9，独立
  CLI 进程无桌面版凭证上下文）。七格交互话术与判定标准见 `docs/b4-matrix.md`，
  建议按原设计在桌面版逐格新会话实测（历史参照：格 3 曾 PASS 后因更名作废）。

## 环境差异备忘

| 差异 | 说明 |
|---|---|
| kimi skill 目录 | `~/.kimi-code/skills/`（`~/.kimi/skills/` 为旧版遗留，0.42 不发现） |
| kimi `-p` = auto | 永不询问、自动执行写操作；批准门控退化为"用户字面指令=默认范围批准"。交互 TUI 下门控完整 |
| 让渡可见性 | 旧项目级 skill 在 `.zcode/skills/` 仅 ZCode 可见；claude/kimi 走通用程序（AGENTS.md+内联挖掘），结果等价路径不同 |
| `~/.zcode` 路径耦合 | skill 正文硬编码的母本/模板路径在本机（zcode 共存）三环境可达，格 3 实测 kimi 成功读 G 层母本；无 zcode 机器走内置回退 |
| claude 子调用告警 | `[claude-code:unrecognized_model] kimi-for-coding`：用户 claude 配置里有自定义模型路由，不影响主流程 |
